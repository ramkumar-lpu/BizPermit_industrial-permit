## 1. Definite TLS Root-Cause Analysis

### Empirical Investigation Findings
Through repeated socket and OpenSSL handshakes through Docker Desktop's internal proxy (`http.docker.internal:3128`), we captured the exact TLS certificate chains presented when contacting `auth.docker.io:443`:

1. **Gateway TLS Interception Detected:**
   - **Interception Entity:** Sophos Network Security Gateway (NSG) (Campus/Enterprise network firewall).
   - **Issuer CN:** `Sophos SSL CA_gmXSmNOqrVD2iZx`
   - **Issuer Organization:** `C=GB, ST=Oxfordshire, O=Sophos, OU=NSG`
   - **Issuer Email:** `support@sophos.com`
   - **Serial Number:** `41:DA:34:82:3E:0D:72:E4:84:BE:C5:D4:6F:A2:17:67:4A:F4:0B:AF`
   - **Validity:** `Aug 1 00:00:00 2015 GMT` through `Dec 31 23:59:59 2036 GMT`
   - **X509 Extension:** `Netscape Comment: generated by HTTP Proxy`
   - **OpenSSL Return Code:** `verify error:num=19:self-signed certificate in certificate chain`

2. **Intermittent / Multi-Route Behavior:**
   - On direct non-intercepted routes, `auth.docker.io` returns Let's Encrypt `CN=YE1` -> `Root YE` -> `ISRG Root X2` -> `ISRG Root X1`.
   - On routes subject to deep packet inspection by the institutional gateway, `auth.docker.io` is dynamically re-signed with `Sophos SSL CA_gmXSmNOqrVD2iZx`.

3. **Why Docker Desktop Fails:**
   - The Docker Desktop engine (`dockerd`) runs inside a dedicated WSL2/LinuxKit VM (`docker-desktop`).
   - The VM's default root certificate bundle (`/etc/ssl/certs/ca-certificates.crt`) only includes standard public WebPKI CAs.
   - When `dockerd` contacts `auth.docker.io/token` to authenticate image pulls, Go's `crypto/x509` certificate verifier rejects the Sophos certificate with:
     `Get "https://auth.docker.io/token?account=...": tls: failed to verify certificate: x509: certificate signed by unknown authority`.

## 2. Safe CA Trust Remediation Procedure (User Action Required)

To safely resolve this without disabling TLS verification or configuring insecure registries:

### Option A: Install Gateway CA in Docker Desktop Registry Trust Directory (Recommended)
Docker Engine natively supports per-registry trusted root certificates on Windows without modifying global system files:

1. Create the Docker certificate directories on your Windows host:
   ```cmd
   mkdir "%USERPROFILE%\.docker\certs.d\auth.docker.io"
   mkdir "%USERPROFILE%\.docker\certs.d\registry-1.docker.io"
   ```
2. Save the institutional Sophos Root CA certificate into both directories as `ca.crt`:
   - Destination 1: `%USERPROFILE%\.docker\certs.d\auth.docker.io\ca.crt`
   - Destination 2: `%USERPROFILE%\.docker\certs.d\registry-1.docker.io\ca.crt`
3. If your Windows host already has the Sophos root CA in `certmgr.msc` -> **Trusted Root Certification Authorities**:
   - Open `certmgr.msc`.
   - Locate `Sophos SSL CA_gmXSmNOqrVD2iZx`.
   - Right click -> **All Tasks** -> **Export...** -> Base-64 encoded X.509 (.CER).
   - Copy the exported file as `ca.crt` into the two directories above.
4. Restart Docker Desktop from the system tray.

### Option B: Switch to an Unfiltered Network
If you are connected via an institutional Wi-Fi/LAN (e.g., campus network) with Deep Packet Inspection:
1. Temporarily connect via an alternative connection (e.g., mobile hotspot or network without MITM inspection).
2. Run `docker pull <image>` to pull required images.
3. Reconnect to your preferred network; already cached local images do not require external registry verification.

## 3. Kong Configuration Resolution

### Previous Issue
In `docker-compose.supabase.yml`:
`entrypoint: bash -c 'eval "echo \"$$(cat ~/temp.yml)\"" > ~/kong.yml && /docker-entrypoint.sh kong docker-start'`
Because `eval "echo \"...\""` performs shell word-splitting and unquoting, YAML double quotes (such as `_format_version: "2.1"`) were stripped, turning `"2.1"` into float `2.1` and corrupting declarative configuration parsing.

### Fix Implemented
1. Updated `docker-compose.supabase.yml` `supabase-kong` entrypoint:
   ```yaml
   entrypoint:
     - /bin/sh
     - -c
     - |
       sed -e "s|\$${SUPABASE_ANON_KEY}|$$SUPABASE_ANON_KEY|g" -e "s|\$${SUPABASE_SERVICE_ROLE_KEY}|$$SUPABASE_SERVICE_ROLE_KEY|g" /home/kong/temp.yml > /home/kong/kong.yml && exec /docker-entrypoint.sh kong docker-start
   ```
2. Created companion entrypoint script `infra/supabase/kong-entrypoint.sh` for maintainability and local validation.
3. Verified that:
   - `_format_version: "2.1"` retains double quotes bit-for-bit.
   - `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are safely interpolated without `eval`.
   - `docker compose -f docker-compose.supabase.yml config --quiet` passes with return code `0`.
   - `docker compose -f docker-compose.supabase.yml --profile dev config --quiet` passes with return code `0`.
